# P2.9 — Sanctions & note de conduite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the Surveillant Général record per-student disciplinary sanctions (the section-G ladder + consignes) and an optional note de conduite (/20), managed on a dedicated per-class discipline page and surfaced on the bulletin's Conduite section — all display-only, never entering the moyenne générale.

**Architecture:** One enum + two Ash resources (`SanctionEntry` flat log, `ConductMark` per-séquence /20). A new `Academics.Discipline` context wraps CRUD + per-période aggregation, reusing P2.8's `Academics.period_date_range/1`. A dedicated discipline LiveView records/manages both; the existing P2.8 bulletin Conduite section (screen + print) is extended with sanctions, consignes count, and note de conduite. Access reuses P2.8's `conduct_manager?`/`admin_or_form_master?`.

**Tech Stack:** Elixir, Ash 3, AshPostgres, Phoenix LiveView, gettext (FR default + EN).

## Global Constraints

- Ash 3 house style on every resource: `use Ash.Resource, otp_app: :teacher_assistant, domain: TeacherAssistant.Academics, data_layer: AshPostgres.DataLayer, authorizers: [Ash.Policy.Authorizer]`; `policy always() do authorize_if always() end`; `uuid_v7_primary_key :id`; `timestamps()`; FK `on_delete` inside `postgres do ... references do ... end end`.
- Enums are `Ash.Type.Enum` modules — never bare `:atom`.
- Context functions call Ash with `authorize?: false`, return tagged tuples, never leak raw Ash errors.
- Double-gating on every web surface: a UI `:if` gate AND a server-side re-check in each mutating handler. Resolve the class via `Academics.fetch_owned_class_group/2`. Targets (enrollments, sanctions) come from socket-loaded collections, never raw client ids. The sanction `type` arrives through a whitelist (no `String.to_atom`/`String.to_existing_atom` on raw input). Numeric input (note value, duration days) parsed and range-checked.
- Conduct is DISPLAY-ONLY: sanctions and the note de conduite must NOT enter the moyenne générale. The P2.3/P2.6 bulletin arithmetic (`Bulletins`, `class_results_for_period`) is not modified.
- Access reuses P2.8: `Permissions.conduct_manager?/1` (SG/admin) mutates; the class form master (`admin_or_form_master?/2`, not conduct_manager) is read-only; everyone else redirected. No new permission helpers are needed.
- Migrations via `mix ash.codegen <name>` then `mix ecto.migrate`; commit the generated migration and `priv/resource_snapshots/` changes.
- Every new user-facing string is a gettext msgid with non-empty FR and EN msgstrs. `mix precommit` (full suite) must be green; its `format` step rewrites files in place — commit format-only diffs. (The precommit alias flag `--warning-as-errors` is misspelled and a no-op, so warnings do not gate; confirm the suite passes regardless. A known `user_fixture` email-collision flake on `users_unique_email_index` can trip an async full run — re-run to confirm if only that fails.)
