# I4 — Passage rules and end-of-year decisions (N10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A school sets its passage rules; each class's annual council sees a proposed decision per student (Admis, Admis par rachat, Redouble, Exclu) with its reason, confirms or overrides it, and the decision appears frozen on the annual report card.

**Architecture:** Settings on `SchoolProfile` feed a pure `Academics.PassageRules` struct with `propose/2`. I3's councils are generalised from a term to a **period** (`{:trimester, term}` or `{:annual, year}`), keyed by `period_key` like I2 publications; `CouncilDecision` gains `passage_decision`; `Councils.outcomes/3` adds the passage for the annual council. `ReportCards` carries and requires the annual council; the council screens, procès-verbal and report cards show the passage.

**Tech Stack:** Elixir, Phoenix LiveView 1.8, Ash 3, AshPostgres, Tailwind v4 + daisyUI, Gettext.

**Spec:** `docs/superpowers/specs/2026-09-27-mockups-roadmap.md`, section "I4 — Passage rules and end-of-year decisions (spec)" (builds on I1–I3 in the same file).

## Global Constraints

- Defaults: passing 10, rachat 9.5 (nil = off), exclusion below 7 (nil = off), one repeat per cycle on, exclusion on conduct < 10 on (10 fixed), exclusion at ≥ 60 unjustified hours (nil = off). Validation among set values: 0 ≤ exclusion_below < rachat_min ≤ passage_min ≤ 20; absence hours > 0.
- Proposal order: Exclu (average < exclusion_below · conduct < 10 · unjustified hours ≥ limit) → Admis (≥ passing) → Admis par rachat (≥ rachat) → Redouble, or Exclu « Déjà redoublant » for a repeater with the one-repeat rule. No average → no proposal. No conduct mark → conduct rule not applied.
- Annual publishing requires the class's annual council held (`{:error, :council_not_held}`).
- Councils keyed by `period_key` = `Organization.period_param(period)` (`"trim:<id>"` / `"annee"`); one council per (class, period_key).
- Writes admin axis only; councils locked while their period is published.
- Never hand-edit migrations (`mix ash.codegen --dev`, then named codegen); if the generator orders a tenant index before `workspace_id`, fix it in the resource (declare `belongs_to :workspace` first) as in I3.
- Gettext: extract, fill new `en`, fix NEW fuzzy entries in en AND fr (compare with main).
- Worktree `.claude/worktrees/i4`, branch `i4-passage`, `MIX_TEST_PARTITION=2`, explicit `git add` paths only.
- Finish with `mix precommit`, `mix ash.codegen --check`, `mix compile --warnings-as-errors`.

## Review Focus

1. An average exactly on a threshold (10.00, 9.50, 7.00) takes the upper decision; nil thresholds switch their rule off — Task 1.
2. A student with no annual average (no marks) gets no proposal and the passage column shows "—" without crashing — Tasks 1, 3.
3. A trimester council created by I3 code paths keeps working after the period refactor (key "trim:<id>"), including lock and hold — Task 2.
4. Annual figures read once per class (no per-student queries) — Task 2.
5. A version-2 snapshot (I3, no `passage` in outcomes) renders the annual card with an empty "Décision" — Task 4.
