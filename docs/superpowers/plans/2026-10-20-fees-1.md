# Fees 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fee types paid in a set order, school-wide percentage tranches, payments that write numbered, frozen,
checkable receipts (QR + typed code, WhatsApp), optional carry-over of last year's arrears, recovery figures, and
the fee screens linked from the bursar's, Proviseur's and Censeur's menus.

**Architecture:** New tenant resources `FeeType`, `ClassFee`, `PaymentAllocation`, `StudentArrear`; `FeeTranche`
moves from per-class amounts to per-year cumulative percents; `FeeAdjustment` gains a fee type; `Payment` gains a
number, a status (valid/cancelled) and frozen figures and loses update/destroy. The pure `Academics.FeeBalance`
holds the arithmetic (dues, allocation, balance, recovery). `TeacherAssistant.Fees` records a payment in one
transaction (advisory lock → number, allocation, frozen figures). The web layer adds a receipt print view, a public
check page (`ReceiptVerification`, modelled on `BulletinVerification`), three LiveViews and menu entries.

**Tech Stack:** Phoenix 1.8 LiveView, Ash 3 (attribute multitenancy, policies), AshPostgres, EQRCode, Gettext.

**Spec:** `docs/superpowers/specs/2026-10-19-fees-1-design.md` (rules numbered there; « rule N » below refers to it).

## Global Constraints

- Worktree `.claude/worktrees/fees-1`, branch `fees-1`, `MIX_TEST_PARTITION=3` for every `mix test`. Stage explicit
  paths only (never `git commit -a`).
- Migrations only with `mix ash.codegen` (final one named `fees_1`); `mix ash.codegen --check` clean at the end.
- Ash enums, never bare `:atom` attributes: `FeeTypeKind` (`:regular | :arrears`), `PaymentStatus`
  (`:valid | :cancelled`).
- Composite FKs `match_with: [workspace_id: :workspace_id]`; `match_type: :full` for required FKs, `:simple` with
  `on_delete: {:nilify, [col]}` only for nullable ones.
- Writes on the fees axis (`{Checks.SchoolRole, any_of: :fees}`); reads: fees axis, plus the class's form master
  for payments/balances of their class (as today). Every new year-bound resource has `YearOpen` (rule 8).
- Amounts integer FCFA, `Date`s, « today » = `Reference.today/0`. Money shown with `TeacherAssistantWeb.Money`.
- Receipt number `R<start year>-<6 digits>` (`R2026-000123`), `seq` per (school, academic year) from 1.
- French msgids, English translations; after `mix gettext.extract --merge` fill and unflag every fuzzy entry.
- `mix precommit` does not fail on warnings: also run `mix compile --warnings-as-errors` (two warnings already on
  main: `marks_live.ex:197`, `my_day_live.ex:293`, leave them).
- Fixed French copy: « Reçu n° %{number} », « Reçu annulé », « Reçu introuvable », « Trop-perçu »,
  « Reliquat année précédente », « Reporter les reliquats de l'année précédente », « non réinscrit »,
  « Encaisser », « Envoyer par WhatsApp », « Recouvrement », « Paramètres des frais »,
  « Copier l'année précédente », « Même montant pour tout le niveau », « À compléter : %{classes} »,
  « Numéro du reçu », « Code ».

## Review Focus

1. Two payments recorded at the same moment for the same school get two different consecutive numbers, never a
   duplicate and never a crash shown to the bursar (test in Task 4).
2. A payment, then a class amount change, then a reprint: the receipt and the check page still show the figures
   given to the parent (test in Task 4).
3. A check-page token or number/code from school A never shows school B's data, and a forged or truncated token
   shows « Reçu introuvable » without a crash (tests in Task 5).
4. A student whose fees are fully paid pays again (a parent pays ahead): accepted, allocated to the last type, the
   balance shows « Trop-perçu » (tests in Tasks 2 and 4).
5. A teacher (no fees role) opening `/school/fees`, a receipt print URL, or crafting `record_payment` /
   `cancel_payment` events gets redirected / refused, nothing written (tests in Tasks 7 and 8).

### Task 2: Pure arithmetic (`Academics.FeeBalance`)

**Files:** Modify `lib/teacher_assistant/academics/fee_balance.ex`; Test `test/teacher_assistant/academics/fee_balance_test.exs` (rewrite).

**Interfaces** (all pure; a type is `%{id, position}` in payment order; `due` and `paid` are `%{type_id => int}`):
- `dues(type_ids, class_amounts :: %{type_id => int}, arrears :: int, arrears_type_id | nil, adjustments :: %{type_id => int}) :: %{type_id => int}` — rule 10, never negative.
- `allocate(amount, ordered_type_ids, due, paid) :: [{type_id, int}]` — rule 11: in order, each gets
  `min(left, max(due - paid, 0))`; the remainder goes to the last type; zero entries dropped.
- `balance(ordered_type_ids, due, paid, tranches :: [%{due_date, percent}], on_date) :: %{by_type: [%{type_id, due, paid, left}], total_due, total_paid, left, due_to_date, status}` — rule 13; `due_to_date = div(total_due * pct, 100)` with `pct` the percent of the latest tranche with `due_date <= on_date` (0 before); `status` `:paid_up | :on_track | :behind`.
- `recovery([balance]) :: %{students, expected, expected_to_date, collected, rate, rate_to_date, behind}` — rule 14;
  rates integer percent, 0 when the denominator is 0.
