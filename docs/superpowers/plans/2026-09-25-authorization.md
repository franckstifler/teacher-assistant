# Authorization (Increment C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Ash policies the single authority over who reads and writes what inside a school: scope threaded through every domain call, real policies with `authorize :by_default` on every domain, composite tenant FKs, `Permissions` retired, and the fee-adjustment sign fixed.

**Architecture:** Three phases. Phase 1 is inert plumbing: role axes + two `SimpleCheck`s, scope-aware test support, a controller `Plug.Scope`, composite FKs (which let us delete `Tenancy.same_workspace/1`), and `%Scope{}`-first signatures in every domain (domains stay `:when_requested` with allow-all policies, so passing the actor changes nothing). Phase 2 writes each domain's policies and flips it to `:by_default`, one domain per task, replacing that domain's `Permissions` call sites. Phase 3 adds the navigation gate and layout capability map, deletes `Permissions`, and runs the final gates.

**Tech Stack:** Elixir, Phoenix 1.8 / LiveView 1.2.12, Ash 3.33.9, AshPostgres 2.13.1, AshPhoenix 2.3.25, AshAuthentication, PostgreSQL ≥ 15.

**Spec:** `docs/superpowers/specs/2026-09-24-authorization-design.md` (read it first; this plan argues from it). Background: `docs/audits/2026-09-23-school-focus/README.md` §8–§10.

## Global Constraints

- Pinned versions (do not upgrade): Ash 3.33.9, AshPostgres 2.13.1, AshPhoenix 2.3.25, LiveView 1.2.12.
- Role model: three axes plus the admin gate, defined **only** by `TeacherAssistant.Accounts.SchoolRole.axis/1`: `:member` any role (active membership); `:admin` = `:head, :vice_principal`; `:head` = `:head`; `:conduct` = `:head, :vice_principal, :discipline_master`; `:fees` = `:head, :vice_principal, :bursar`. No capability matrix, no delegation construct.
- Display-only roles (`:hod`, `:guidance_counsellor`, `:librarian`, `:teacher`) carry no authority beyond membership.
- Operate gate (`SchoolVerified`) covers marks and attendance writes only.
- Operator (`User.role == :admin`) gets no school data beyond the school list and verification actions.
- `authorize?: false` in `lib/` only at the places listed in the Phase 3 gate (Task 19); each carries a comment saying why.
- Migrations: iterate with `mix ash.codegen --dev`; finish every schema-changing task with `mix ash.codegen <slug>` (squashes the `_dev` files). Never commit a `_dev` migration, never hand-write a migration.
- Per-task gate, in order: `mix ash.codegen --check`, `mix compile --warnings-as-errors`, `mix test`, `mix precommit`. (`mix precommit` misspells its warnings flag and does not gate on warnings; its `format` step rewrites files — commit after it.)
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>` (state this in every subagent dispatch; subagents default to their own model name).
- Phoenix 1.8 conventions from `AGENTS.md`: `<Layouts.app flash={@flash} current_scope={@current_scope} current_path={@current_path}>`, `<.input>`, `<.icon>`, no inline scripts. New copy is French source strings through `gettext`.

## Conventions (every task's requirements include these)

### C1 — Scope-first signatures

Every public domain function that touches tenant data takes `%TeacherAssistant.Scope{}` as its **first** argument:

- it replaces a `%Workspace{}` argument: `list_class_groups(ws, year)` → `list_class_groups(scope, year)`;
- functions that took only child structs gain it: `delete_class_group(cg)` → `delete_class_group(scope, cg)`;
- pre-tenant entry points take a scope carrying only the user: `create_school(scope, attrs)`, `accept_invitation(scope, token)`, `list_workspaces_for(scope)`;
- a "who did it" argument (`recorded_by_user_id`, `issued_by_user_id`, `inviter`) is **dropped**; the domain uses `scope.current_user.id` (a caller can no longer attribute a write to someone else);
- `Workspaces.scope_for/3` builds the scope and stays scope-free; pure helpers with no DB access keep their signatures;
- code-interface functions generated by `define` keep Ash's convention: callers pass `scope: scope` in the trailing opts.

### C2 — Ash calls inside domains and resources

- Pass `scope:` to the **builder** when there is one — `Ash.Query.for_read/4`, `Ash.Changeset.for_create/4`, `for_update/4`, `for_destroy/4`, `Ash.ActionInput.for_action/4` — and delete the following `set_tenant/2`. Otherwise pass it to the executing call: `Ash.get/3`, `Ash.load/3`, `Ash.destroy/2`, `Ash.read/2` (on a bare `Ash.Query.filter` pipeline), code interfaces.
- Delete every struct-derived tenant (`set_tenant(x.workspace_id)`, `tenant: x.workspace_id`, `tenant_of/1`).
- Inside a resource callback (generic action `run fn input, ctx ->`, `change`, `validate`, `prepare`, `after_action`), the callback's context **is** the scope: `scope: ctx` / `scope: context`. It implements `Ash.Scope.ToOpts` (actor, tenant, authorize?, shared context).
- Cross-domain calls pass the scope along.

Before/after example:

```elixir
# before
def list_tranches(%ClassGroup{id: cg_id, workspace_id: ws_id}),
  do: list_tranches_for_class_group_id!(cg_id, tenant: ws_id)

# after
def list_tranches(%Scope{} = scope, %ClassGroup{id: cg_id}),
  do: list_tranches_for_class_group_id!(cg_id, scope: scope)
```

```elixir
# before (inside Mark :upsert_all)
|> Ash.Changeset.for_create(:create, attrs)
|> Ash.Changeset.set_tenant(tenant)
|> Ash.create(return_notifications?: true)

# after
|> Ash.Changeset.for_create(:create, attrs, scope: ctx)
|> Ash.create(return_notifications?: true)
```

### C3 — Web layer

- LiveViews pass `socket.assigns.current_scope` (or `@current_scope` in templates) as the first argument.
- AshPhoenix forms: `tenant: x` → `scope: scope` (so `submit` carries the actor).
- `start_async`/`Task`: bind `scope = socket.assigns.current_scope` **before** the closure and use the variable inside it.
- Controllers read `conn.assigns.current_scope` (set by `Plug.Scope`, Task 3).

### C4 — Tests

- Fixture maps carry the head's scope as `scope` (Task 1). Pass it wherever the test acts as the head; build another actor's scope with `school_scope(user, workspace)` or `member_scope_fixture(scope, %{roles: [...]})`.
- A non-member scope is built by hand: `%TeacherAssistant.Scope{current_user: outsider, current_workspace: ws}`. An actor-less scope: `%TeacherAssistant.Scope{current_workspace: ws}`.
- Phase 1 leaves raw `Ash.*` calls in tests alone. Phase 2 (per domain) replaces `authorize?: false` and `tenant:` on that domain's resources with `scope: <acting scope>`.

### C5 — Forbidden passes through (Phase 2)

A domain write that the policy refuses returns `{:error, %Ash.Error.Forbidden{}}` — never a collapsed atom, never a raise. When converting a domain:

```elixir
# a case that collapses errors
{:error, %Ash.Error.Forbidden{} = forbidden} -> {:error, forbidden}
{:error, _error} -> {:error, :tranche_failed}

# a bang call inside try/rescue
rescue
  e in Ash.Error.Forbidden -> {:error, e}
  _ -> {:error, :adjustment_failed}
```

A bare bang call (`Ash.destroy!(e, ...)`, e.g. `Enrollment.withdraw/2`) becomes the non-bang call returning `:ok | {:error, error}`.

### C6 — LiveView handlers (Phase 2)

Delete the `Permissions` pre-check; call the domain; render the shared flash on `Forbidden`:

```elixir
# before
with true <- Permissions.fees_manager?(scope),
     {:ok, amount} <- parse_amount(params["amount"]) do
  case Fees.add_tranche(scope, socket.assigns.cg, attrs) do
    {:ok, _} -> ...
    {:error, _} -> {:noreply, put_flash(socket, :error, gettext("Could not add the tranche."))}
  end
else
  _ -> {:noreply, socket}
end

# after
with {:ok, amount} <- parse_amount(params["amount"]) do
  case Fees.add_tranche(scope, socket.assigns.cg, attrs) do
    {:ok, _} -> ...
    {:error, %Ash.Error.Forbidden{}} -> {:noreply, Authz.put_not_allowed(socket)}
    {:error, _} -> {:noreply, put_flash(socket, :error, gettext("Could not add the tranche."))}
  end
else
  _ -> {:noreply, socket}
end
```

Visibility (buttons, forms, sections) uses the domain's `can_*?` functions, computed **once in `mount`** into assigns — never in `render`.

### C7 — Boundary tests (Phase 2)

Each domain gets `test/teacher_assistant/authorization/<domain>_test.exs` calling the **real domain functions**: authorized role ✓, wrong role ✗, non-member ✗, actor-less ✗, owner ✓ / other teacher ✗ where ownership applies, and for sensitive reads a plain teacher gets empty while the class's form master reads. Use `assert_forbidden/1` (Task 1).

## Review Focus

1. **Signed-out invitee opening or accepting an invitation link.** The page must still show the school name (Workspace reads become member-only) and `POST …/accept` while signed out must redirect to sign-in with `return_to`, not crash (today `accept_invitation(token, nil)` raises `FunctionClauseError`). Pinned in Task 3 (accept redirect) and Task 17 (school name).
2. **The operator's `/admin/schools` list.** It must still show each school's name and owner email after Workspace and User reads are restricted. Pinned in Task 17 (User read admits the operator — a clarification of spec §4.2) and Task 9 (Workspace read admits the operator).
3. **A member revoked while their LiveView is open.** The next write must be refused with the shared flash, not a crash or a generic "could not save". Pinned by C5 in every Phase 2 task and by the revocation test in Task 17.
4. **Deleting a `CombinedCourse` whose contexts still point at it** (outside `split`). Plain `ON DELETE SET NULL` on the new composite FK would null `workspace_id` too and violate NOT NULL. Pinned in Task 4 (`{:nilify, [:combined_course_id]}` + test).
5. **A teacher recording marks or attendance in an unverified school, or for a context they do not own.** Refused at the data layer, not just hidden. Pinned in Tasks 12 and 13.

        subject: attrs[:subject] || "Maths"

      teacher: teacher,
      membership: membership,
      class_group: class_group,
      teaching_context: tc,
      scope: school_scope(teacher, workspace)
    }
  end

defmodule TeacherAssistant.Accounts.Checks.SchoolRole do
  @moduledoc """
  Policy check: the actor holds an **active** membership in the subject's school
  whose roles intersect `SchoolRole.axis(any_of)`.

      authorize_if {TeacherAssistant.Accounts.Checks.SchoolRole, any_of: :admin}

  The school is the subject's tenant; for the two non-tenant school resources
  it comes from the record (`Workspace.id`, `SchoolProfile.workspace_id`). No
  actor, no resolvable school or no active membership → `false`. The
  membership is read fresh on every check, so a revoked member is refused on
  their next call, even inside an open LiveView.
  """
  use Ash.Policy.SimpleCheck

  alias TeacherAssistant.Academics.Workspace
  alias TeacherAssistant.Accounts.{SchoolMembership, SchoolProfile}
  alias TeacherAssistant.Accounts.SchoolRole, as: Roles

  @impl true
  def describe(opts), do: "actor holds a #{inspect(opts[:any_of])} role in the school"

  @impl true
  def match?(actor, %{subject: subject}, opts),
    do: holds?(actor, workspace_id(subject), Keyword.fetch!(opts, :any_of))

  def match?(_actor, _context, _opts), do: false

  @doc "Whether `user` holds a role of `axis` in the school `workspace_id` (fresh read)."
  def holds?(%{id: user_id}, workspace_id, axis) when is_binary(workspace_id) do
    case active_roles(user_id, workspace_id) do
      nil -> false
      roles -> axis == :member or Enum.any?(roles, &(&1 in Roles.axis(axis)))
    end
  end

  def holds?(_user, _workspace_id, _axis), do: false

  @doc "The school a policy subject (query, changeset or action input) belongs to."
  def workspace_id(%{resource: Workspace, data: %Workspace{id: id}}) when is_binary(id), do: id

  def workspace_id(%{resource: SchoolProfile, data: %SchoolProfile{workspace_id: id}})
      when is_binary(id),
      do: id

  def workspace_id(%{tenant: %{id: id}}), do: id
  def workspace_id(%{tenant: id}) when is_binary(id), do: id
  def workspace_id(_subject), do: nil

  # Check-internal read: `authorize?: false` because a policy check must not
  # recurse into the policies it is part of.
  defp active_roles(user_id, workspace_id) do
    SchoolMembership
    |> Ash.Query.for_read(:for_workspace_and_user, %{user_id: user_id})
    |> Ash.Query.set_tenant(workspace_id)
    |> Ash.read_one(authorize?: false)
    |> case do
      {:ok, %SchoolMembership{roles: roles}} -> roles
      _ -> nil
    end
  end
end

defmodule TeacherAssistantWeb.Plug.Scope do
  @moduledoc """
  Assigns `current_user` and `current_scope` for controller routes, the way
  `TeacherAssistantWeb.LiveUserAuth` does for LiveViews: the signed-in user
  (AshAuthentication's `current_user` assign, else the session `user_id`) and
  `Workspaces.session_scope/3` for the session's school and teaching context.
  Runs after `TeacherAssistantWeb.Plug.Locale`.
  """
  @behaviour Plug

  import Plug.Conn

  alias TeacherAssistant.Accounts
  alias TeacherAssistant.Accounts.Workspaces

  @impl true
  def init(opts), do: opts

  @impl true
  def call(conn, _opts) do
    user = conn.assigns[:current_user] || Accounts.session_user(get_session(conn, :user_id))

    scope =
      Workspaces.session_scope(
        user,
        get_session(conn, :workspace_id),
        get_session(conn, :context_id)
      )

    conn
    |> assign(:current_user, user)
    |> assign(:current_scope, %{scope | locale: conn.assigns[:locale] || "fr"})
  end
end

Why `match_type: :simple` for nullable: `MATCH FULL` would reject a null FK next to the non-null `workspace_id`; `MATCH SIMPLE` allows the null and checks a non-null value.

Every Phase 2 task:

1. adds `alias TeacherAssistant.Accounts.Checks` to each resource and replaces its `policies do policy always() do authorize_if always() end end` with the block given;

An action with no applicable policy is forbidden — that is intended for unused default actions. If a test exercises one, switch the test to the action the domain actually uses.
