# Ash Framework compliance audit — teacher-assistant

Audited against `.claude/skills/ash-framework/**` (Ash, AshPhoenix, AshPostgres, AshAuthentication, AshOban usage rules) and `AGENTS.md`. Read-only; nothing was edited. `mix ash.codegen --check` was run (exit 0 — snapshots and migrations are in sync).

## 1. Summary

- 32 resources across 9 small domains, all on `AshPostgres`, all with `Ash.Policy.Authorizer` declared — but **30 of them carry `policy always() do authorize_if always() end`**, every domain is `authorize :when_requested`, and **no call site anywhere (domain or web) passes `actor:`/`scope:`**. The data layer enforces nothing; authorization lives in `Accounts.Permissions` + LiveView gates. This is known and is the subject of `docs/superpowers/specs/2026-09-23-authorization-hardening-design.md`, but it remains the single largest deviation from the rules.
- **Business logic lives in plain domain functions rather than actions.** Domains are 240–960 line modules of hand-rolled `Ash.Changeset.for_create |> Ash.create` / `Ash.Query.for_read |> Ash.read!` wrappers, ad-hoc validations (`validate_amount`, `validate_type`, range-checks), multi-step orchestration without transactions, and error-to-atom mapping. Only ~45 `define`s exist; `code_interface` on resources: 0; `AshPhoenix` domain extension (`form_to_*`): not used.
- **Tenant/ownership scoping is manual.** No `multitenancy`; every read action takes `workspace_id` as an argument, and every create *accepts* `workspace_id` from input. Several `workspace_id` / `*_by_user_id` columns are bare `:uuid` attributes with no `belongs_to` → no FK constraint.
- **No FK indexes at all** (`index?: false` on every reference in every snapshot) despite every hot query filtering on `workspace_id`, `class_group_id`, `enrollment_id`, `progression_plan_id`, etc.
- Three `:atom` attributes still use `constraints: [one_of: ...]` instead of `Ash.Type.Enum` (project rule).
- Several **N+1 / per-row loops** where a single read, aggregate, `Ash.exists?`, or bulk action would do; `bulk_*` and `Ash.exists?` are used nowhere.
- 9 inline anonymous `change fn` / `prepare fn` / `after_action(fn ...)` where the rules ask for modules; 3 `require_atomic? false` (all reasonably justified).
- Data layer: 1 hand-written data migration (`20260811220000_backfill_progression_modules.exs`) and one hand-edited generated migration; a stale `personal_workspaces` snapshot directory remains.
- Tests: no `Ash.Generator`, no policy tests (`Ash.can?` = 0), 237 direct `Ash.*` calls and 131 `authorize?: false` sprinkled through resource tests, one raw `Repo.delete`.
- AshOban / AshArchival / AshStateMachine / Oban / oban_web / cinder are dependencies and (for Oban) configured, but **unused**; Oban is not even in the supervision tree.
